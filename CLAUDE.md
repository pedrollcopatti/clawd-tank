# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Clawd Tank is a macOS menu bar app that shows what your Claude Code sessions are
doing. Claude Code hooks report every session's activity over a Unix socket to a
daemon, which tracks per-session state and drives a status bar icon plus a
popover listing each live session.

Everything is one process: a `rumps` status bar app on the main thread with the
asyncio daemon on a background thread.

> Clawd Tank began as an ESP32-C6 hardware display ("the tank"), with the Mac app
> as a control panel. The device, its firmware, the SDL2 simulator and the BLE
> transport were removed in favour of the menu bar being the whole product. Git
> history has all of it if you need to look something up. The name stayed: the
> bundle id, launchd label, `~/.clawd-tank/` and the socket path all depend on it.

## Build Commands

```bash
# Build the .app bundle and install to /Applications
cd host && ./build.sh --install

# Build without installing
cd host && ./build.sh
```

`build.sh` runs py2app against `host/.venv`. The bundle is self-contained — no
helper binaries, no Bluetooth permission.

### Tests

```bash
# All tests — use the host venv
cd host && .venv/bin/pytest -q

# A single file
cd host && .venv/bin/pytest tests/test_session_state.py -v

# If the venv needs setup:
cd host && python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
```

### Icons

```bash
# Regenerate the status bar icons and popover sprites
python3 tools/make_menubar_icons.py
python3 tools/make_menubar_icons.py --only waiting   # just one
```

Stdlib only. Reads the frame stills in `assets/clawd-frames/`; the original
animated SVGs are in `assets/svg-animations/` (rendering those needs
`tools/svg2frames.py`, which requires playwright + chromium).

## Architecture

### Data flow

```
Claude Code hooks (SessionStart / PreToolUse / PostToolUse / PermissionRequest /
                   PostToolUseFailure / PreCompact / Stop / StopFailure /
                   Notification / UserPromptSubmit / SessionEnd /
                   SubagentStart / SubagentStop)
    → ~/.clawd-tank/clawd-tank-notify        (stdlib-only hook handler)
    → Unix socket ~/.clawd-tank/sock
    → ClawdDaemon                            (background asyncio thread)
        ├→ per-session state machine → sessions.json (survives restarts)
        ├→ alert sounds (afplay)
        └→ build_session_snapshot() → observer → ClawdTankApp (main thread)
                                                  ├→ status bar icon + title
                                                  └→ NSPopover session rows
```

### `host/clawd_tank_daemon/`

- **daemon.py** — `ClawdDaemon`: socket server, per-session state machine,
  staleness and PID-liveness eviction, subagent tracking, alert sounds, and the
  `DaemonObserver` push. `build_session_snapshot()` is the pure function that
  turns internal state into the UI's view; pushes are debounced 150 ms and
  suppressed when unchanged. Single-instance via a lockfile + PID file.
- **protocol.py** — `hook_payload_to_daemon_message()`: Claude Code hook stdin → daemon message.
- **socket_server.py** — `asyncio.start_unix_server` on `~/.clawd-tank/sock`, mode 0600.
- **session_store.py** — atomic save/load of session state to `~/.clawd-tank/sessions.json`.
- **pid_resolver.py** — walks `ps` ancestry to find the long-lived `claude` PID.

### `host/clawd_tank_menubar/`

The pure/AppKit split is deliberate and structural: the pure modules import no
AppKit, so their logic is testable where there is no window server. Don't
collapse them.

- **app.py** — `ClawdTankApp(rumps.App, DaemonObserver)`. Owns the daemon thread,
  marshals observer callbacks to the main thread via `AppHelper.callAfter`.
- **status_icon.py** — *pure*. Session snapshot → aggregate state → icon name and title.
- **session_view_model.py** — *pure*. Snapshot → `RowModel`s: sprite, project, detail text, elapsed, accent.
- **session_row.py** — AppKit. Builds one row's `NSView`s. Popover-agnostic on purpose.
- **popover.py** — AppKit. `NSPopover`, status item click routing, the while-open refresh timer.
- **hooks.py** — the embedded `clawd-tank-notify` script (stdlib only) plus a
  matcher-aware, non-clobbering merge into `~/.claude/settings.json`.
- **preferences.py** — `~/.clawd-tank/preferences.json`, with a one-shot prune of obsolete keys.
- **launchd.py**, **version.py** — launch at login, version string.
- **icons/** — generated by `tools/make_menubar_icons.py`; `icons/rows/` are the popover sprites.

### Status item

rumps assigns the status item an `NSMenu`, which swallows button clicks. On
`rumps.events.before_start` the menu is detached and clicks are routed by hand:
left opens the popover, right (or ctrl-click) re-attaches the menu and pops it.
If that ever breaks, the fallback is a custom-view `NSMenuItem` holding the same
rows — which is why `build_session_row()` knows nothing about popovers.

Icons are **colour, not template images**: a template is drawn from alpha alone,
which flattens the crab to a blob and loses the red "!" and the error stars that
distinguish the states.

### Session state model

- **Per-session states**: `registered` → `thinking` → `working` → `idle`, plus
  `waiting` (blocked on you), `confused` (a tool failed) and `error` (StopFailure).
- **Aggregate icon priority**: `error` > `waiting` > `working` > `thinking` > `idle` > none.
  `waiting` outranks `working` because it's the only state that needs you to act.
- **Staleness eviction**: no events within the configured timeout (default 10 min)
  → evicted. `waiting` sessions are exempt: they legitimately emit nothing while
  they wait for you.
- **PID liveness**: every 30 s, a session whose `claude` PID is gone is evicted.
- **Subagents**: `SubagentStart`/`SubagentStop` track active `agent_id`s per session.
- **Persistence**: written atomically on structural change, so restarting the app
  preserves state for running sessions. Stale entries are pruned on load.

## Key Constraints

- **macOS only** — AppKit via pyobjc, `afplay`, `launchctl`.
- **pyobjc comes transitively** through rumps; there is no direct dependency on
  it and no WebKit. Don't add a framework dependency to the bundle lightly: it
  ships unsigned and unnotarized.
- **Everything the UI touches must be main-thread.** The daemon runs on another
  thread; go through `_schedule_main()`.
- **Popover timers exist only while it's open.** A permanently scheduled 1 Hz
  timer would wake the process every second for the app's whole life.
